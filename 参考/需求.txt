[LAYOUT & UI SPEC] (三栏式界面布局与自适应规范)

游戏界面必须由左、中、右三块独立的区域组成（比例约为 1:2:1，使用HTML/CSS Grid或Flexbox实现自适应），并强制执行以下防拉伸与比例锁定规范：

1. 左侧：关卡印象图 (Stage Impression Panel)
   · 动态渲染与当前关卡主题高度契合的抽象向量背景（例如：1面为流动的绿色文本行，2面为错乱的系统故障红字，3面为代表分歧的双向发光流线，A线为高冷科技感的铬色网格，B线为夕阳西下的福州暖色调几何色块）。
2. 中间：版面 (Playfield - Canvas)
   · 物理画布与逻辑分辨率分离原则：
     · 游戏逻辑必须采用固定逻辑分辨率（Logical Resolution）：450px * 600px。
     · HTML中，Canvas标签物理尺寸属性必须固定：<canvas id="playfield" width="450" height="600"></canvas>。
     · 禁止在JavaScript运行中修改 canvas.width 和 canvas.height，所有游戏实体的坐标更新、碰撞半径、飞行速度均基于该 450 * 600 逻辑坐标系计算。
     · CSS防拉伸自适应：
       ```css
       #playfield {
           width: 100%;
           height: 100%;
           object-fit: contain; /* 核心：保持4:3的450x600比例，多余空间留白，防止画面拉伸 */
           aspect-ratio: 450 / 600;
           display: block;
           margin: auto;
       }
       ```
3. 右侧：分数版 (Score & Control Panel)
   · 上方信息区：显示当前的高分（Hi-Score）、得分、残机数、Bomb数、编辑度（进度条）以及Unstable Machine状态。
   · 下方触屏键区：在分数版的最下方，为移动端触屏玩家设置“Item”和“Bomb”两个虚拟按键。

[INPUT & MOBILE CONTROLS] (输入与移动端相对移动适配)

· 移动端相对移动控制（Touch-and-Drag Relative Movement）：
  · 核心逻辑：为避免手指遮挡自机和判定点，并且防止初次触摸时自机发生瞬间移动（Warping），必须采用“相对位移控制”。
  · 实现流程：
    1. 当触发 touchstart 时，记录当前触点在 450 * 600 逻辑坐标系下的位置 (startTouchX, startTouchY)，同时记录此时自机的坐标 (startPlayerX, startPlayerY)。
    2. 当触发 touchmove 时，获取当前最新触点的逻辑坐标 (curTouchX, curTouchY)。
    3. 计算触点的逻辑位移增量：deltaX = curTouchX - startTouchX，deltaY = curTouchY - startTouchY。
    4. 更新自机位置：player.x = startPlayerX + deltaX，player.y = startPlayerY + deltaY。
    5. 限制自机范围：自机位置必须被限制在 [0, 450] 和 [0, 600] 逻辑边界之内。
  · 触控坐标映射公式：
    ```javascript
    function getLogicalTouchPos(touchEvent, canvas) {
        const rect = canvas.getBoundingClientRect();
        const clientX = touchEvent.touches[0].clientX - rect.left;
        const clientY = touchEvent.touches[0].clientY - rect.top;
        const logicalX = clientX * (canvas.width / rect.width);
        const logicalY = clientY * (canvas.height / rect.height);
        return { x: logicalX, y: logicalY };
    }
    ```
  · 自动射击 (Auto-Shot)：在移动端，当玩家手指接触屏幕版面时，自动激活“Shot键”高频开火，松开手指时暂停开火。
  · 触屏辅助键：在【分数版】最下方的“Item”和“Bomb”虚拟按键拥有独立的Touch监听器，供另一只手随时点击触发。

核心故事背景

“饮泉思源・才华的水”作为百京维基神守护着“门构皮蒂娅(moregirl pedia)”，她原本以为这样美好的生活会一直这样下去。直到“门构皮蒂娅”被“铬”接管，她察觉到了一个事实：“门构皮蒂娅”可能会变质，但永远不会倒闭。随后她将目光投向了新生的“OTTOWikiProject”上，加入了这个组织。
OTTOWikiProject原本只有“爱丽丝”、“Icebin”、“大宗关不是・互然雏”、“一美个”四个人。
OTTOWikiProject在她和“誓约沙玛”的加入后变得蒸蒸日上。但好景不长，几个月后一美个成为了叛徒，它在任职期间一直在OTTOWikiProject中埋下隐患，于是它被OTTOWikiProject菲比委员会调查并逐出。
尽管一美个被逐出，OTTOWikiProject却急转直下，变得几乎无人问津。
饮泉思源和誓约沙玛作为OTTOWikiProject的核心人物，认为问题的答案一定在门构皮蒂娅或者善雅乡。准备去一探究竟。

游戏核心机制

· 默认资源: 2残3b
· Letter card: 充当传统弹幕游戏中的“符卡（Spellcard）”概念。
· 章节系统: 道中每段，boss每个Letter card为一个章节，当章节内没有使用bomb或者被弹，该章节结束时所得分数*1.05。
· unstable machine: 每个道中章节获得随机效果，正负10以内的攻击力或分数获得加成、视野迷雾、bomb禁用、双倍bomb消耗。按照负面效果影响补偿章节所得分数倍数，正面不进行补偿或惩罚。
· Graze与编辑战: 当自机判定点靠近子弹时，会积累“编辑度（Edit Progress）”能量槽。当编辑度攒满后，玩家可以按下Item键触发一次“编辑战”。这会以自机为中心，将周围半径50像素内的子弹消除并转化为“高分道具”。
· 决死bomb: 当自机被子弹击中时，游戏不会立刻判定Miss，而是会进入一个约0.15~0.2秒的“审核中（Arbitration Pending）”停滞状态，此时屏幕上会闪烁“违规编辑！”提示。如果玩家在这个极短的时间内按下了Bomb键，就会消耗1个Bomb触发“菲比委员会强制撤销”。自机免于坠机，并触发全屏消除弹幕。

[SPECIFIC BULLETS DEFINITIONS] (具体弹种定义)

1. 小玉 (Dot Bullet): 直径8px圆形，判定半径3px。在Canvas中以 ctx.arc 配合渐变色绘制。
2. 米弹 (Rice Bullet): 12px * 6px 椭圆形，判定半径2px。在Canvas中以旋转的 ctx.ellipse 绘制。
3. 札弹/代码札 (Talisman Bullet): 16px * 8px 矩形（代表代码行），判定半径4px。在Canvas中以旋转的 ctx.rect 绘制。
4. 中玉 (Medium Ball): 直径16px圆形，判定半径6px。
5. 大玉 (Large Ball): 直径32px圆形，判定半径12px。
6. 激光 (Laser Beam): 宽度为10px的半透直线。

结局A：不倒闭的真理

在一阵剧烈的弹幕爆炸中，“一美个”的“哈机密乐园”彻底崩溃。他痛苦地捂着脑袋，被“铬”自动运行的系统清理大师判定为“垃圾”，直接无情地拖入了回收站。
饮泉思源与誓约沙玛终于来到了“门构皮蒂娅”与“OTTOWikiProject”的数据主控制台前。她们满怀敬畏地试图寻找拯救维基、让组织重焕新生的终极奥秘。
然而，屏幕上并没有什么高深的魔法或伟大的代码，只有一个弹窗提示：
“您的服务器由于欠费5美元已暂停解析，请及时续费。”
原来，“门构皮蒂娅”在被“铬”接管后，通过无限循环的算法广告实现了永不倒闭；而“OTTOWikiProject”之所以急转直下、无人问津，根本不是因为什么神秘的诅咒或背叛，只是单纯因为创始人忘记了给服务器续费，导致所有用户访问时都显示“502 Gateway Error”。
饮泉思源叹了口气，从“一美个”战败掉落的零钱包里摸出了五张一美元的纸币投了进去。
伴随着“叮”的一声，OTTOWikiProject重新上线，爱丽丝、Icebin、大宗关等人瞬间收到了服务器恢复的邮件通知，编辑者们陆续回归，组织再次蒸蒸日上。维基的危机得以解决，世界重归平静。

结局B：散去的幻影

伴随着最后一个Letter card of the boss的碎裂，“拉斯特神炫”发出了一声悲鸣，他赖以维系的“炫妈的温度与味道”结界在弹幕的冲击下轰然瓦解。
神炫哭喊着“炫妈……我的炫妈……”跌落了防空洞，而他一直贴身珍藏、用以散发“炫妈香气”的神秘宝瓶也随之摔得粉碎。
刹那间，那股传说中让无数人心醉神迷、甚至让神炫彻底黑化的“炫妈味道”瞬间弥漫了整个善雅乡。饮泉思源和誓约沙玛本以为会遭遇精神污染，却在闻到气味的瞬间愣住了——
这股独特的味道，其实只是福州特产虾油（鱼露）混杂了大量清凉薄荷风油精的刺激性气味。
由于宝瓶碎裂，这股高浓度的“虾油风油精”气味顺着服务器的散热风扇，直接倒灌进了OTTOWikiProject的物理主机房。
这股极度刺鼻、提神醒脑的虚拟气味竟然顺着网络信号线，化作了物理级别的物理防盗防火墙。任何企图顺着网线对OTTOWikiProject进行恶意破坏、灌水或恶意编辑的黑子和水军，在打开网页的瞬间都会被电脑屏幕前逸散出的刺鼻气味熏得泪流满面、无法呼吸，不得不狼狈关闭网页。
至此，对OTTOWikiProject的恶意破坏彻底停止，维基的安全得到了物理层面的永久保障。虽然从此以后，每一位登录维基进行编辑的词条作者都必须戴上防毒面具，但大家都由衷地赞美着这来之不易的和平。
