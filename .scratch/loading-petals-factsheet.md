## 3. ANM 指令语义（从 `anm_vm.cpp` 读出，**这是权威**）

| 指令 | 语义 | 证据 |
|---|---|---|
| `ins_300(n)` | `set_sprite(n)` 选当前精灵 | `anm_vm.cpp:76` |
| `ins_302(arg)` | 写字节 `+0x498` = arg，并清 `+0x4a0` 的 0x30 位（混合模式） | `:78` |
| `ins_303/304/305/306/307` | 写字节 `+0x499`（层/优先级） | `:79-83` |
| `ins_311(arg)` | 写 `+0x4a0` 的 bit2-3 = `(arg&3)<<2` | `:87` |
| `ins_313(arg)` | 写字节 `+0x4a4` = arg，置 `flags[1]|0x800000` | `:89` |
| `ins_431(arg)` | `flags |= (arg&1)<<7` | `:123` |
| **`ins_400(x,y,z)`** | **写位置 `vector_2c` = (x,y,z)**（若 `flags[1]&0x40` 则写 `vector_484`） | `:96` |
| `ins_401(x,y,z)` | 写 `vector_38`（另一条位置/锚点）并置 `flags[1]|2` | `:97` |
| `ins_402(x,y)` | 写 `vector_50`（缩放）并置 `flags[1]|4` | `:98` |
| `ins_403(arg)` | 写字节 `+0x493`（**当前 alpha**） | `:99` |
| `ins_404(r,g,b)` | 写 `+0x492/0x491/0x490`（当前颜色） | `:100` |
| **`ins_407(dur, mode, x, y, z)`** | **位置插值**：`duration=dur`，`mode=mode`，起点=当前 `vector_2c`，终点=(x,y,z)，`timer=0` | `:103-104` |
| `ins_408(dur,mode,r,g,b)` | 颜色插值（起点=当前色） | `:105` |
| **`ins_409(dur, mode, end)`** | **alpha 插值**：起点=当前 `+0x493`，终点=end | `:106` |
| `ins_113/115/117/119` | 浮点运算写入当前浮点寄存器：`113=+`、`115=-`、**`117=×`**、**`119=÷`** | `:64` |
| `ins_101/103/105/107/109` | 浮点寄存器 `= / += / -= / *= / =` | `:51-61` |
| `ins_200(offset, time)` | 跳转（循环） | `:72` |
| `ins_501(script)` | 生成子脚本（flags=4） | `:131` |

**参数寻址规则**：参数从指令头部 `+8` 起按 **16 位半字**排列；`I(ins,i)` 取第 i 个 int16，`F(ins,i)` 取 `float at +8+4i`（`anm_vm.cpp:96-106` 的用法与 `thanm.c:475` 的格式串 `"SSfff"` 一致）。
**`mode` 即插值缓动号**，与我们 STD 背景那份是同一套（共 32 条，`ecl_vm/math.cpp:34-52`）：`0=线性`，`9=缓入缓出`，`4=另一种缓动`。

## 4. 解出来的动画（可确证部分）

### L2「Now Loading」— `script15`（`ascii.anm.txt:1707-1734`）

```
-1: ins_302(0); ins_300(sprite913); ins_431(1); ins_307(1);
    ins_400(192, 32, 0);          // 初始位置 x=192, y=32
    ins_304(53); ins_313(2); ins_403(0); ins_311(1);
 8: ins_407(4, 4, 32, 32, 0);     // 4 帧内：x 192 → 32（mode 4 缓动），y 恒为 32
    ins_409(8, 0, 255);           // 8 帧内 alpha 0 → 255（线性）
+30: // 38
    ins_0();                       // 一个 tick 的空操作
offset172:
    ins_409(30, 9, 255);          // alpha → 255（mode 9 缓入缓出）
+30: // 68
    ins_409(30, 9, 128);          // alpha → 128
+30: // 98
    ins_200(offset172, 38);        // 回跳 ⇒ 60 帧一个「255↔128 呼吸」循环
    ins_5(1);
    ins_407(30, 4, 240, 32, 0);    // 30 帧内 x → 240，y 不变
    ins_409(30, 0, 0);             // alpha → 0（淡出）
+30: // 128
    ins_1();                       // 绕回脚本开头
```

⇒ **这块有横向位移（x: 192→32→240），y 恒为 32，没有纵向运动。** alpha 是呼吸 + 末段淡出。

### L1「少女祈祷中」— `script14`（`:1681-1705`）

`ins_400(0, 0, 0.01)` 定位后进入：`ins_409(8,0,255)` 淡入 → `ins_409(20,9,255)` ↔ `ins_409(20,9,128)` 循环。
⇒ **静态文字 + 20 帧一档的 alpha 呼吸**（255↔128）。

### L3「莲花」— `script16`（`:1736-1777`）

由 `script17`（`:1779-1785`）**每 4 帧重放一次**（`ins_501(script16)` + `ins_200(offset84, 1)`）。
脚本内用 `ins_113/115/117/119` 做浮点运算写寄存器，再用 `ins_400/407` 取计算结果定位；其中可读到 `ins_119(..., 80.0f)` 这类**除以 80** 的缩放运算。

## 5. 必须诚实标注的不确定项

1. **莲花的运动轨迹我没能完全算出来**。`script16` 的寄存器编号（10004-10012）映射到 `thanm` 的 `gvar_names`（全局变量名表），但**该表不在 thtk 仓库里**，是按游戏逐代提供的。没有它，我无法确定 10004/10005/10010/10011 各代表什么（可能是位置/速度/角度）。
   ⇒ **我能确证"Now Loading 是横向漂移 + 呼吸"，但"莲花是否下落"仍未确证。**
2. `mode` 缓动号 4 与 9 的确切曲线形状我只知道「4 是某种缓动、9 是缓入缓出」，具体公式在 `math.cpp:34-52` 有，需要时可查。
3. 屏幕上的实际缩放/放置（640×480 还是其它分辨率）未确认。
4. `script18` 是另一套初始化，我只读了开头，未完整解码。

## 6. 对实施方案的含义

- **不要抄贴图**：这是东方原作资源。`assets/NOTICE.md` 已把 BGM 按官方二创指南标注为受限，原作图像素材同属受限范围。**我们应自绘花瓣贴图**（项目已有 AI 生成 + AVIF 流程，`NOTICE.md:21-27`，用 `tools/to-avif`）。
- **值得抄的是结构**：一张切好的图 + 每块一条小时间轴，对**位置（`ins_407`）+ alpha（`ins_409`）+ 颜色（`ins_408`）**做插值，缓动号复用同一套。**成本远低于粒子系统**。
- **"变速"在这里是免费的**：TH20 的 ANM 时间推进用 `timer_tick(timer, env::timer_rate())`（`anm_vm.cpp:218,248`），而 `timer_rate` 就是全局 `clock_scale` 的别名；精灵的旋转/位移速度也乘同一倍率（`:252-254`）。⇒ **动画时钟与游戏时钟共用一个旋钮**，这是引擎级设计。
- 我们的等价落点：`index.html:13-36` 的 `#load-screen`、`css/style.css:99-131` 的 `load-bg`（**目前零动画**）、`js/main.js` 的 `setLoadProgress` 进度链路。
